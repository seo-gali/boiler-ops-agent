02 / RUN IT YOURSELF

실제 화면으로 확인하세요.

이번 개정의 실제 화면입니다. 빌드와 통합 E2E 13개 항목을 확인했고, 원본 대조와 급탄기 감사 결과를 새 검증 기록에서 볼 수 있습니다. 이전 결과서와 이미지도 보존합니다.

설비를 찾고, 기간을 보고, 질문을 이어갑니다.

  1. 센서 선택: 공장의 설비를 눌러 모든 센서 상태를 봅니다. 묶음과 센서는 선택 상자로 고릅니다. 오른쪽 상세는 설비 → 묶음 버튼 → 센서 선택 순서이며 전체 118개에 접근할 수 있습니다.
  2. 기간 비교: 위쪽 메뉴에서 설비·센서를 골라 여러 개를 추가합니다. 같은 단위는 색으로 비교하고 다른 단위는 그래프를 나눕니다. 마우스·터치·방향키로 원본 시각과 값을 확인합니다.
  3. AI 대화: 예시와 메시지를 고정된 대화 영역에서 보고 하단에 입력합니다. Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 다른 설비를 골라도 질문 대상은 유지되며 초안·조회 중 X로 닫으면 먼저 확인합니다.
  4. 배치: 5분 예측은 공장 아래에서 함께 봅니다. 승인 연습·변경 기록은 각각 메인 메뉴에서 엽니다. 센서 상세의 추이와 표는 최근 원본 120초만 표시합니다.

7개 논리 설비 110개 + 주증기 지표 5개 + 발전 지표 2개 + 위치 미확인 1개 = 118개 센서입니다. 그림과 움직임은 탐색용이며 실제 설치 위치·위험도를 뜻하지 않습니다.

단위는 어디에서 확인했나요?

원본 컬럼 정의서 CustomExcelView.xlsx와 센서명 118개를 정확히 연결했습니다. 출력 MW · 주증기 유량 T/H · 압력 kg/cm2g · 온도 °C · 산소 %를 표시하며 숫자와 음수는 환산·보정하지 않습니다.

목표 온도의 결측은 유지합니다. 급탄기 13개는 전체 50,400행에 결측·파싱 오류가 없으며 2025-03-28 11:15 이후 모두 원본값 0입니다. 실제 원인은 미확인입니다. 별도 보일러 제원 9행과 운전 데이터의 발전소 연결 관계도 미확인입니다.

무엇이 실행되어 있어야 하나요?

API 8000 · 화면 5173 · Kafka 9092 · Ollama 11434. 모든 서버는 로컬에서 실행합니다. 브라우저 주소와 APP_PUBLIC_ORIGIN은 같아야 합니다.

03 / BOUNDARIES & EVIDENCE

어디에서 검증하고,
무엇을 막는가.

검증된 범위와 남은 한계를 분리해서 기록합니다. 상세 기록도 페이지 안에서 읽을 수 있습니다.

요청이 통과하는 네 개의 문

  1. 01Origin·Host·입력 크기
  2. 02만료 세션·역할·사용자 소유권
  3. 03요청량·모델 작업·연결·저장 한도
  4. 04근거 나이·재생 세션·단일 사용·revision
Kafka 생산자와 소비자SASL + ACL
질문·Trace·제안·Audit사용자별 접근
키보드·모바일·차트 대체 정보브라우저 검수

로컬 데모에서 검증한 경계입니다. 외부 배포, 실제 스크린리더 낭독, 설비 제어의 안전성을 인증하는 결과는 아닙니다.
