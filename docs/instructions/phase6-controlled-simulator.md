# Phase 6 — 연습용 변경안과 사용자 승인

실제 설비의 제어 허용 범위는 확인되지 않았다. Simulator는 승인 절차를 연습하는 기능이며, 단위 없는 `demo_bias` 숫자만 바꾼다. 실제 밸브나 보일러 온도의 반응을 계산하지 않는다.

데모 정책 `local-demo-v1`에서는 값이 −10~10이고 한 번에 −1·0·1만큼 바뀐다. 코드에서 이 변경 단위는 `simulation_step`이다. 이 범위를 산업 안전 기준으로 설명하지 않는다.

본인의 재열기 AI 조회 기록(Trace)을 연결하면 로컬 모델이 요청에서 증가·유지·감소(`increase/hold/decrease`)를 선택한다. 변경안을 만들 때는 아직 값이 바뀌지 않는다. 로그인한 운영자가 별도로 확인하고 승인해야 실행한다.

제안의 값은 승인 요청에서 바꿀 수 없다. 제안은 5분 뒤 만료되며 현재 변경 횟수(`revision`)와 일치해야 한다. 거절하거나 이미 처리한 제안은 실행하지 않는다. 승인·값 변경·결과 기록(Audit)은 하나의 SQLite 저장 작업으로 묶어 함께 성공하거나 취소한다.

공유 승인 토큰은 사용하지 않는다. 로그인 세션의 운영자 역할·제안 소유권을 검사하고, 본인의 성공한 재열기 Trace가 현재 재생 run과 연결되는지 제안·승인 시 다시 확인한다. 인증과 근거 경계는 [보안 계약](phase7-security-hardening.md)을 따른다. E2E의 임시 계정 자격은 로그·아티팩트에 기록하지 않는다.

승인·거절 응답이 유실되면 화면은 POST를 자동 반복하지 않고 GET으로 결과를 재확인한다. 미확인 상태와 수동 재확인·재시도는 [승인 결과 보완 계약](phase7-workspace.md#승인조회http-관측-보완)을 따른다.
검증: 미승인 불변, 잘못된 자격 거부, 브라우저 승인, 거절, 재실행 차단, 변경 Trace.
