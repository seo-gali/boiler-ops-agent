# Phase 7 — 캐시 없이 읽기·화면 갱신·비동기 호출 정리

2026-11-03 로컬 작업 기준이다. 원본 CSV·기존 DB·패키지 버전은 바꾸지 않았다. 공개 배포는 이 검증에 포함하지 않는다.

## 데이터 구조에서 줄인 작업

[CSV 읽기](../../backend/app/replay/csv_source.py)는 행을 평평한 셀 목록으로 전달한다. [기간 조회](../../backend/app/domain/history.py)는 선택한 열만 사용하며, 매 행마다 전체 센서 사전을 만들지 않는다. 재생 프로그램에 필요한 원본 Tag 사전은 기존 형식을 유지한다.

기간 안의 시각·원본 문자열·숫자를 각각 별도 배열에 둔다. 숫자는 Python의 연속 숫자 배열인 `array('d')`, 유효값·파싱 실패 여부는 관측당 1비트인 비트셋으로 표현한다. 출력할 원본 행은 정수 인덱스로 고른다. 원본 문자열·결측·파싱 실패·빈 구간·CSV 행 번호는 기존 응답과 같다.

CSV 시간 인덱스와 최근 16개 조회 결과를 보관하던 캐시를 삭제했다. 문서 이미지 크기 함수의 캐시, React의 `memo`·`useMemo`·`useCallback`, 같은 관측에 대한 예측 응답 재사용도 제거했다. 현재 관측·최근 기록·화면 입력과 Scene 리소스는 실제 앱 상태로 유지한다. 운영체제와 설치된 라이브러리의 내부 동작은 변경하지 않았다.

[센서 추이](../../frontend/src/SensorTrend.tsx)는 이미 시간순인 두 기록을 한 번씩 읽어 합친다. 해시 테이블 생성 후 재정렬하던 과정을 없앴다. [실시간 화면](../../frontend/src/App.tsx)은 값이 바뀌는 HTML 영역에서 구독하며, [3D](../../frontend/src/BoilerScene.tsx) 전체를 다시 그리지 않는다. 움직이는 점은 기존 좌표 객체에 위치를 기록해 매 프레임 새 좌표 객체를 만들지 않는다.

Python·JavaScript에서는 직접 스택 할당이나 포인터 상위 비트 압축을 적용하지 않았다. 3D 점의 참조는 길이 3의 튜플로 제한하지만 스택에 저장된다는 뜻은 아니다. 인증·소유권과 원본 Tag 사전, 작은 메타데이터 그룹은 배열로 바꾸지 않았다.

## 자주 실행되는 비동기 경로 확인

애플리케이션의 `await`, Promise 체인과 호출부를 확인했다. 검사·영상 제작 스크립트의 순차 시나리오는 실제 서비스 경로와 구분했다.

| 경로 | 판단과 조치 |
| --- | --- |
| [Kafka 수신](../../backend/app/streaming/consumer.py) | 배치 읽기와 주기적인 토픽 확인을 함께 시작한다. 둘 중 하나가 실패해도 두 읽기가 끝난 뒤 연결을 정리한다. |
| [WebSocket 배포](../../backend/app/websocket/hub.py) | 큐에 즉시 넣는 함수라 async와 호출부의 await를 제거했다. 구독자별 큐 한도·초과 알림은 유지한다. |
| [예측·도구·Trace API](../../backend/app/main.py) | 파일 읽기를 기존 스레드 실행기로 넘긴다. 예측·도구가 사용할 관측은 넘기기 전에 고정한다. 다른 API 요청이 파일 읽기를 기다리지 않는다. |
| Kafka 상태 적용·커밋·배포 | 적용 성공 뒤 커밋하고 화면에 배포하는 순서를 유지한다. 오류 처리와 재연결도 유지한다. |
| 데이터 재생 | 토픽 확인 → 연결 → 전송 확인 → 재생 간격 대기 순서가 필요하다. 전송을 무제한 병렬화하지 않는다. |
| AI 질의 | 모델이 도구를 고른 뒤 근거를 수집하고, 그 근거로 다음 모델 호출을 한다. 앞 결과가 필요하다. 도구는 대부분 같은 고정 관측의 메모리 읽기라 별도 병렬 실행기를 만들지 않는다. 모델 작업은 이미 이벤트 루프 밖에서 실행한다. |
| 기간 비교 | 브라우저는 센서를 하나씩 조회하고 서버는 CSV 읽기를 합계 2개까지 허용한다. 서버 과부하를 막는 기존 계약이라 유지한다. |
| 승인·거절·재확인 | 쓰기 결과 뒤에 재조회해야 한다. 응답을 잃었을 때도 쓰기를 반복하지 않는 처리를 유지한다. SQLite 작업은 이미 기존 실행기를 사용한다. |
| 로그인·레지스트리·실시간 연결 | 인증 뒤 레지스트리 조회와 WebSocket 연결은 독립적으로 시작한다. HTTP 응답을 받은 뒤 본문을 읽는 단계는 앞 결과가 필요하다. |
| 추이·예측·기록 화면 | 각 화면이 필요한 요청을 독립적으로 시작한다. Trace는 펼칠 때, 추가 기록은 이전 커서로 조회한다. 방문하지 않은 화면의 요청을 앞당기지 않는다. |
| WebSocket 송수신·종료 | 송신·수신 작업은 이미 함께 실행한다. 연결 종료 시 취소와 자원 정리는 완료를 기다린다. |

## 같은 CSV로 읽기 비교

기존 커밋 `813db08`과 수정본을 같은 프로세스에서 번갈아 세 번 실행했다. 기존 버전은 매번 결과·인덱스 캐시를 비운 뒤 읽었다. 50,400행 CSV에서 하루 구간의 1,441개 관측을 읽고 1,000개 원본 표본을 반환했다.

| 측정 | 기존 실제 읽기 | 수정한 실제 읽기 |
| --- | ---: | ---: |
| 3회 중앙값 | 1,596 ms | 571 ms |
| Python 추적 기준 최대 메모리 | 3,023,373 B | 573,242 B |

이 측정에서 실제 읽기는 약 2.8배 빨랐고 추적 메모리는 약 81% 줄었다. 전체 JSON 응답은 동일했다. 운영체제 파일 캐시는 유지되며 물리 디스크의 첫 읽기를 재현한 시험은 아니다. 메모리는 별도 `tracemalloc` 실행에서 측정해 시간 측정과 분리했다.

기존 캐시 적중은 별도 실행에서 약 0.05 ms였다. 캐시를 제거한 반복 조회도 이제 파일을 읽으므로 이보다 느리다. 캐시 적중과 실제 읽기를 섞어 속도가 개선됐다고 설명하지 않는다. 동시 사용자 부하·실제 Kafka 지연·운영체제 전체 메모리는 측정하지 않았다.

## 검증

먼저 기존 CSV 캐시와 직렬 대기·파일 읽기 차단이 검사에서 실패하는 것을 확인한 뒤 수정했다.

| 명령 | 확인한 내용 |
| --- | --- |
| `.venv/Scripts/python.exe scripts/check-api-performance.py artifacts/data-oriented-api-green.json` | 입력·SQL·CSV·비트셋 경계·원본 보존, 파일 읽기 중 다른 API 응답, Kafka 읽기 중첩·실패·정리·커밋 순서 |
| `.venv/Scripts/python.exe scripts/check-operational-reliability.py artifacts/data-oriented-reliability.json` | 실제 ASGI 인증 경계, CSV 공통 한도·취소, HTTP 오류·지연·비밀값 제외 |
| `npm --prefix frontend run build` | TypeScript·배포용 빌드·청크 크기 |
| `node scripts/check-telemetry-performance.mjs` | 동일 관측·변하지 않은 센서 구독, 재생 실행 변경, 2분 추이·화면 정지·예측 재조회 |
| `node scripts/check-bundle-performance.mjs --reliability` | 실제 Chromium·WebGL의 선택·카메라·지연 로딩·AI 탐색·승인·CSV 취소 |

위 명령은 모두 종료 코드 0으로 통과했다. API 검사는 47개, ASGI 신뢰성 검사는 20개, 브라우저 묶음 검사는 17개 항목을 확인했다. 새 관측 10개를 보낼 때 SceneCanvas 재렌더는 0회였고 JavaScript 청크는 모두 500 kB 이하였다.

`scripts/build-guide.py`로 미리보기 70개를 갱신했다. `scripts/check-pages-seo.py`는 검색 대상 문서 27개와 내부 링크 307개를 확인했고, `node scripts/review-ui.mjs`의 문서 브라우저 검사와 `git diff --check`도 통과했다.

API 검사에서는 임시 CSV, 메모리 SQLite, 가짜 Kafka 클라이언트와 격리 서비스를 사용했다. 브라우저 검사는 합성 API·WebSocket을 사용했다. 실제 Kafka·Ollama·운영 DB를 연결한 전체 E2E 결과로 설명하지 않는다. 측정 JSON과 검사 출력은 로컬 `artifacts/`에 남긴다.

## 문서와 코드의 차이 정리

이전 화면 지침의 최근 16개 조회 캐시 요구와 시스템 설계 문서의 캐시 설명을 이번 동작에 맞춰 수정했다. 과거 성능 결과 문서는 당시 캐시·React 메모화가 있던 버전의 기록이므로 그대로 두었다. 현재 기준은 [화면 지침](../instructions/phase7-workspace.md)과 이 결과 문서에서 확인한다.
